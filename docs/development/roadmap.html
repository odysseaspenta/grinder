Roadmap

Recommended changes after 4.1.0, most important first. Each one is a candidate for its own issue and pull request.

1. Protect the web console and REST API

The embedded web server binds to every network interface unless grinder.console.httpHost is set, and it has no authentication. Anyone who can reach port 6373 can change console properties, upload files and distribute them to agents, and start workers. Because workers run whatever script they are given, that amounts to running code on every connected agent.

  • Default grinder.console.httpHost to 127.0.0.1, so exposing the console becomes a deliberate choice.
  • Add optional authentication (Spring Security with HTTP Basic or a token from a property) for the REST API and the web UI.
  • Document the risk on the properties page and in the Docker instructions, which publish port 6373.

Port 6372, the agent port, is also unauthenticated. Its protocol is Java serialization, so it should be listed as trusted-network only, and deserialization limited to Grinder message classes with an ObjectInputFilter.

2. Finish moving project metadata off SourceForge

The documentation now points at GitHub for source, issues and contributions. The build still does not:

  • The root pom.xml url, scm, issueManagement and mailingLists elements point at SourceForge and the original project.
  • The groupId io.github.cossme is a namespace this fork cannot publish under. Changing it to io.github.odysseaspenta affects anyone who installed 4.1.0 locally, so do it at a version boundary (4.2.0) and record it in CHANGES.
  • The sourceforge.* and mail.* entries in docs/_data/links.yaml that nothing references any more can be deleted.

3. Ship Windows start scripts or stop documenting them

The README and the user guide show setGrinderEnv.cmd, startAgent.cmd, startConsole.cmd and startProxy.cmd, but the distribution ships only the .sh scripts. Either add .cmd equivalents to the assembly, including a setGrinderEnv.local.cmd hook, or describe them as examples to copy.

4. Automate releases to GitHub

4.1.0 was released by hand. A workflow triggered by a v* tag could run mvn -B verify on Java 21, create the GitHub release and attach the binary zip and its SHA-256. It needs only the built-in GITHUB_TOKEN: no Maven Central, GPG or Docker Hub secrets.

5. Keep dependencies current

Enable Dependabot for the maven and github-actions ecosystems, with Spring Boot, Jython and ASM updates grouped so each update gets one pull request. CI already builds on Java 21 and 25, so each update is tested.

6. Plan for life after Jython 2.7

Jython implements Python 2.7, which upstream Python no longer supports, and Jython 3 is not ready. Scripts written for The Grinder depend on it, so it cannot simply be removed. Options to evaluate:

  • Keep Jython as the default, and make the Clojure and Java script engines first-class, with gallery examples and documentation.
  • Add a GraalPy (Python 3) script engine next to Jython, through the META-INF/net.grinder.scriptengine extension point, and compare its instrumentation support and throughput with tools/perf.

7. Triage open issues from the original project

Some open issues on cossme/grinder may already be fixed by 4.1.0, and others still apply: #17, #18, #25, #26, #27 and #30. Check each against this release, and copy the ones that still apply into this repository's issue tracker.

8. Refresh the documentation

  • Many pages still describe The Grinder 3 and Java 1.4 to 8 era tooling. Review the guide for JDK 21 behaviour, especially the FAQ entries on JVM options and garbage collection.
  • Remove the leftover Apache Forrest site: links, which do not resolve under Jekyll.
  • Add a documentation page for the web console, the default UI since 4.0.
